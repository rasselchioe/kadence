[ 01 ]
DNA

Reading the
references first.

Three sites. Three different jobs. Before any pixels go down for Kadence, here is exactly what I'm stealing — and what I'm leaving behind so this product reads as its own thing, not a remix.
[ 01-A ]  hellohello.is

Studio confidence — warm, indexed, conversational.

  • takeBone/cream paper background with rich warm ink. Bold sans display set tight. Numbered list rhythm: (1), (2), (3).
  • takeSection labels that read like signage. Big questions, short answers. Lots of air between blocks.
  • takeThe whole color world — cream, ink, a single hot accent — becomes Kadence's main palette.
  • leaveStudio bio copy, the global clock-row chrome, multilingual hello.
[ 01-B ]  outfit.hellohello.is

Boutique inventory — index, label, breathe.

  • takeTight product grid energy: small monospace metadata, big quiet imagery, page counters like 000 / 014.
  • takeCompact metric labels above big values. Same pattern reads beautifully on stat cards.
  • takeStrong whitespace as a feature, not as filler. Single-line nav.
  • leaveE-commerce affordances, cart, sizing, anything store-specific.
[ 01-C ]  marinkurir.com

Personal portfolio energy — playful, indexed, kinetic.

  • takeMassive uppercase display with asterisk separators: MARIN ✱ DIGITAL DESIGNER ✱. Bracketed nav: [ABOUT], [WORK ↓].
  • takeIndexed case study moments: [00-1], [00-2]. Ticker rows. Tiny labels under huge type.
  • takeThe italic-serif accent as a typographic "wink" against the dominant sans.
  • leavePersonal-portfolio tone, emoji smiley, anything that reads as one-person blog.
[ 01-D ]  The translationEditorial → Analytical

The hard part is that these references are all presentational — portfolios and storefronts. Kadence is a working tool: dense, queryable, live with data. So the recipe is to keep the editorial bones — bone paper, monospace labels, ticker chrome, indexed sections, one italic-serif accent — and let the working surfaces (tables, charts, maps) inherit the typographic discipline rather than the layout drama.

In practice: headers are loud and editorial, data is quiet and uniform. The interesting visual moments live at the seams — a marquee at the top of the upload screen, a bracket-labeled climb in an activity, an indexed ride card in the dashboard. Never on the chart itself.

[ 05-E ]  DensityDashboard vs editorial

Two densities, switched per surface:

EDITORIAL — 56 / 96 / 120 vertical rhythm, generous air, 1 idea per row.
WORKING — 12 / 16 / 24 vertical rhythm, 4-up stat rows, 8 visible rides at a glance.

Rule of thumb — if it's a single ride, lean editorial. If it's a comparison or list, lean working.

[ 05-F ]  How editorial & dashboard meetThe Kadence trick

Every dashboard page opens with one editorial moment — a bracketed index, a marquee, or a giant display title — that claims the space. Below it, work happens at working density. The reader gets the postcard before the spreadsheet.

HEADER → editorial · 56–120 type · single line
METRICS → working · 4-up grid · mono numbers
CONTENT → working · tables, charts, panels
FOOTER → editorial · ticker or colofon

[ 08-B ]  Axis, tooltip, empty stateConventions
[ KM 16.4 ]  TUESDAY HILL LOOP
ELEV248 m SPEED14.2 km/h HR172 bpm POWER298 W

Axes — JetBrains Mono 10–11px, hairline rules at the baseline and one above, no gridlines on minor ticks. X labels read in KM, never time, unless the chart is a calendar.

Empty state — a single hairline rule, the metric label, and the line "No rides yet. Drop a GPX to start the line."

Map ↔ chart link — hovering a chart point pulses a crimson dot on the route; clicking pins it both ways. Brushing on the chart highlights the matching map segment in crimson.

[ 09 ]
MOTION

Subtle, not
showy.

Motion is reserved for moments that reward it — first paint of a route, upload progress, transitioning into a ride. Never on hover, never decorative.
[ M-01 ]0.6s
Page transition

A 1px crimson rule sweeps right-to-left across the top, leaving the new content composed beneath. No fades, no slides of cards.

[ M-02 ]1.2s
Route draw-on

When an activity opens, the route line traces from start to end using SVG stroke-dashoffset. Markers fade in at completion.

[ M-03 ]parse
Upload progress

Counter ticks up as trackpoints are extracted — 04210 / 08442. Numbers in JetBrains Mono so widths don't jitter.

[ M-04 ]hover
Hover states

Table rows tint to paper. Buttons invert ink ↔ bone. Chart points show a 1.5px crimson ring. Maps brighten the route by 12%.

[ M-05 ]always
Ticker

The single piece of always-on motion. 18–50s loop depending on width. Pauses on focus (a11y).

[ M-06 ]0.18s
Chart hover

Vertical crosshair snaps to the nearest trackpoint, dot pulses once, tooltip cross-fades. No springs.

[ M-07 ]map
Map interaction

Pan/zoom unaffected. Selecting a chart point eases the map to that coord at 600ms with the camera offset 100px so the popover never covers the segment.

[ M-08 ]respect
Reduced motion

prefers-reduced-motion: reduce kills the ticker, the route draw-on, and the map ease. Everything still works.

PORTFOLIO

Built to be
seen.

Notes on demoing this for a portfolio: which rides to seed, which screenshots to lead with, the case-study shape, and the accessibility floor.
[ 10-A ]  Demo dataSeed once, look real
  • 01 · Seed 52 weeks of rides for one fictional rider — vary distance 12–96 km, two rest weeks, one PR week.
  • 02 · Use real public GPX traces (OSM cycling, Strava public segments) — terrain looks honest.
  • 03 · Include one bad upload (route file with no trackpoints) so the error state is reachable.
  • 04 · Pin a "latest ride" from yesterday's date so the dashboard reads alive.
  • 05 · Provide a "reset demo" button in settings.
[ 10-B ]  README screenshotsOrder matters
  • 01 · Hero — the landing, full-bleed, dark on bone.
  • 02 · Dashboard at "Week 23" — the editorial header + 4-up stats + ride table.
  • 03 · Activity detail with route drawn, climbs highlighted.
  • 04 · Upload preview screen — the moment that proves it parses.
  • 05 · Trends 52-week bars, including the rolling average.
  • 06 · One dark mode view (activity at night).
  • 07 · One error state — so the polish reads beyond happy path.
[ 10-C ]  Case study shapeFor your site

[ 10-D ]  Accessibility floorNon-negotiable
CONTRAST

[ 11-E ]  IntegrationsServer-only keys
  • Open-Meteo — /api/weather?lat&lng&t. No key. Cache 24h by rounded-down hour + 0.01° grid.
  • MapLibre + OSM — self-host the style JSON, raster tiles from OpenStreetMap with a clear attribution in [ MAP ] corner label.
  • OpenRouteService — future. Wrap behind a server route to keep the key off the client.
  • Supabase — magic link only. Service role used only in server actions for the parse pipeline.
